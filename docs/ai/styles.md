# Стили (SCSS)

Как связать стили с макетом и Figma-переменными — `docs/design/figma.md`.

## Основное

- Стили компонента — `ComponentName.module.scss` рядом с view, классы в `camelCase`: `styles.cardTitle`.
- Цвета, отступы, радиусы, шрифты, тени, длительности — только через CSS-переменные из `src/styles/tokens.scss` (`var(--color-accent)`). «Магических» значений в модулях нет.
- Из SCSS используем вложенность (не глубже 3 уровней), `&`-модификаторы и миксины для медиа-запросов. Переменные темы — CSS-переменные, не `$scss` (D-4).
- Варианты и состояния — `data-`/`aria-`атрибуты (`data-variant="ghost"`, `aria-pressed`), стили цепляются за атрибут: `&[data-variant='ghost']`. `className` во view — на усмотрение автора: один класс модуля, склейка нескольких (в том числе глобального `container`) или выбор класса тернарником допустимы (D-29). Инлайн-стили `style={{}}` — только для значений, приходящих из данных.
- Компонент не задаёт себе внешние отступы (`margin`) — расположением управляет родитель. Центрирование тоже: `margin: 0 auto` у компонента запрещён, родитель центрирует через flex/grid (`justify-content`, `align-items`), при необходимости — обёрткой в своём JSX (D-33).
- Общая раскладка компонента и его скелетона — SCSS-partial с миксинами в папке компонента (`ShowList/_grid.scss`), а не импорт чужого `.module.scss`.
- Базовая проверка — ширина 375px. Анимации уважают `prefers-reduced-motion`.

## Отступы и размеры

- Шкала отступов — сетка 4px, номер шага = значение / 4: `--space-1` (4) · `2` (8) · `3` (12) · `4` (16) · `5` (20) · `6` (24) · `8` (32) · `12` (48) · `16` (64) · `20` (80) · `30` (120) (D-18).
- `padding`, `margin`, `gap` — только `var(--space-*)` или `0`. Сырые `px`/`rem` в этих свойствах запрещены.
- Значение вне шкалы в макете (например 10 или 22) — не заводи токен, а приведи к сетке и в Figma, и в коде. Новый шаг добавляется, только если он кратен 4 и нужен макету; имя — по тому же правилу (`--space-10` = 40px), старые имена не перенумеровываются.
- **Кратны 4** (D-35, D-46): отступы, шрифты, высоты строк, скругления, высоты контролов. Исключения — толщина обводки (`border` 1–2px) и `--radius-pill`. Значение вне сетки округляется до ближайшего кратного 4, при равном расстоянии — вверх (14 → 16, 30 → 32).
- **Размеры элементов — любые** (D-46): ширины и высоты блоков, постер, точка логотипа, иконки, максимальные ширины, заглушки скелетона (`<Skeleton width={90} />`), размеры из раскладки (`%`, `fr`, `flex`, по содержимому). Размер элемента — отдельный токен-размер (`--logo-dot-size`, `--poster-width-default`), а не `--space-*` или `--radius-*`, даже если число совпадает.
- Высота контрола (кнопка, чип, поле) — токен `--control-height-*` (`xs` 36 · `sm` 44 · `md` 52) при `box-sizing: border-box`, а не сумма `padding` + строка + рамка: рамка 1px иначе сдвигает высоту с сетки.
- Отступ из макета = `padding` в коде; рамка 1px добавляется поверх (подробно — `figma.md`).

Почему: номер = значение / 4 — по числу из макета сразу видно токен, а вставка нового шага не ломает старые имена. Сетку держат отступы и типографика — из них складывается раскладка.

```scss
// ❌
.field { padding: 0 22px; gap: 14px; }
.dot { width: var(--radius-sm); }

// ✅
.field { padding: 0 var(--space-5); gap: var(--space-3); }
.dot { width: var(--logo-dot-size); }
```

## Шрифт и высота строки

- Размер шрифта — только `var(--text-N)`, номер шага = значение / 4: `--text-3` (12) · `4` (16) · `5` (20) · `8` (32) · `10` (40) · `11` (44) · `18` (72) · `19` (76).
- `line-height` — только `var(--leading-N)` по тому же правилу: `--leading-4` (16) · `6` (24) · `7` (28) · `8` (32) · `10` (40) · `12` (48) · `13` (52) · `18` (72) · `21` (84). Сырые числа, `px`, `em` и `%` запрещены.
- **Каждый блок, где задан `font-size`, задаёт и `line-height`** — в том же селекторе или в том же миксине брейкпоинта. Обычные пары: 12/16, 16/24, 20/28, 32/40, 40/48, 44/52, 76/84; другая пара — если так в макете (логотип 20/24, описание hero 20/32).

Почему: высота строки в px — единственный способ держать строку на сетке 4px (коэффициент 1.2 даёт 33.6px). Готовая длина наследуется как есть, поэтому каждый текст задаёт обе величины сам.

```scss
// ❌ коэффициент: 28 × 1.2 = 33.6px; шрифт без высоты строки
.title { font-size: 1.75rem; line-height: 1.2; }
.hint { font-size: var(--text-4); }

// ✅
.title { font-size: var(--text-8); line-height: var(--leading-10); }
.hint { font-size: var(--text-4); line-height: var(--leading-6); }
```

## Брейкпоинты

- Брейкпоинты — только в `src/styles/breakpoints.scss` (карта `$breakpoints`: `tablet: 768px`, `desktop: 1200px`, `wide: 1440px`; значение — ширина, с которой начинается экран). Миксины попадают во все модули через `additionalData` в `vite.config.ts`, `@use` вручную не нужен. Исключение — partial-файлы из `src/styles/`, подключённые через `@use` (`tokens.scss`): там `@use './breakpoints' as *` пишется явно.
- Медиа-запросы по ширине — только миксинами:
  - `@include screen-from(tablet)` — `tablet` и шире;
  - `@include screen-below(tablet)` — уже `tablet`, только мобильный;
  - `@include screen-between(tablet, desktop)` — от `tablet` включительно до `desktop` не включительно.
- В базе без миксина — только то, что одинаково на всех экранах. Разное значение — в непересекающихся миксинах, без значения в базе (D-21). Три значения — `screen-below(tablet)` + `screen-between(tablet, desktop)` + `screen-from(desktop)`, без перебивания `screen-from(tablet)` через `screen-from(desktop)`.
- Число колонок сетки с пагинацией — делитель размера страницы (D-27): страница — 3 шоу, колонок 1 или 3, задаются брейкпоинтами, а не `auto-fill`.
- Несколько размерных вариантов компонента с несмежными диапазонами — миксины в partial `_variants.scss` в папке компонента (`ShowCard/_variants.scss`: `card-compact`, `card-default`), подключение через `@use '<путь>/variants' as *`. Внутри — только миксины поверх `screen-*`.
- Значение, одинаково адаптивное в нескольких компонентах (`--page-gutter`), — семантический токен в `tokens.scss`, переопределённый в миксинах; компоненты используют его без медиа-запросов. Заводится, только когда значение нужно в двух и более компонентах.
- Адаптивное значение берётся из шкалы токенов. Не хватает шага — добавь его в `tokens.scss`, а не магическое число в модуль.
- Сырые `@media (min-width/max-width/width …)` в модулях запрещены. Новый брейкпоинт добавляется, когда реально понадобился.

Почему: `var()` не работает в условии `@media`, поэтому брейкпоинты живут в SCSS. Непересекающиеся диапазоны: каждое объявление действует ровно на своём экране, в десктопе нет мёртвых мобильных значений.

```scss
// ❌ сырой медиа-запрос
.logo { font-size: 16px; @media (min-width: 768px) { font-size: 20px; } }

// ❌ мобильное значение в базе, на десктопе перебивается
.logo {
  font-size: var(--text-4);
  line-height: var(--leading-6);
  @include screen-from(tablet) { font-size: var(--text-5); line-height: var(--leading-7); }
}

// ✅
.logo {
  font-family: var(--font-display); // одинаково везде — в базе
  @include screen-below(tablet) { font-size: var(--text-4); line-height: var(--leading-6); }
  @include screen-from(tablet) { font-size: var(--text-5); line-height: var(--leading-7); }
}

// ❌ стиль только для мобильного, который потом сбрасывается
.hint { display: block; @include screen-from(tablet) { display: none; } }

// ✅
.hint { @include screen-below(tablet) { display: block; } }
```

## Комментарии в стилях

Правило D-39 действует и здесь: комментарий объясняет неочевидное «почему». Исключение — общие файлы `src/styles/*.scss` и partial-файлы раскладки (`_grid.scss`, `_shell.scss`): там допустимы многострочные пояснения и ссылки на Figma-переменные, потому что это точка связи токенов с макетом (D-51).

## Автопроверка

`pnpm check:arch`: строк ≤ 120, каждая `var(--x)` объявлена в `tokens.scss`, отступы через `--space-*`, `line-height` через `--leading-*`, `font-size` в паре с `line-height`, нет сырых `@media` по ширине, токены шкал кратны 4 и шаг N = N × 4px.
