# Зависимости

По умолчанию ответ на вопрос «добавить пакет?» — **нет**. Каждая зависимость — это код, который придётся обновлять, изучать и когда-нибудь заменять.

## Порядок действий перед добавлением

1. **Можно ли обойтись платформой?** Web API, возможности React, CSS, TypeScript, 20–50 строк своего кода в `utils/` или `hooks/`.
2. Если нет — проверь пакет по критериям:
   - решает задачу целиком, а не тянется ради одной функции;
   - активная поддержка (релизы за последний год), собственные TypeScript-типы;
   - разумный размер в бандле, tree-shaking, минимум транзитивных зависимостей;
   - лицензия MIT / Apache-2.0 / ISC / BSD;
   - совместим с текущими версиями React, Vite, TypeScript.
3. **Согласуй с пользователем**: что за пакет, зачем, какие были альтернативы. Без подтверждения не устанавливай.
4. Установи через `pnpm add` (или `pnpm add -D` для инструментов), **добавь строку в реестр ниже**.
5. Спрячь пакет за своим модулем (хук, функция, компонент в `components/ui`), чтобы остальной код от него не зависел и замена затрагивала один файл.

## Правила

- Менеджер пакетов — только pnpm. `package-lock.json` и `yarn.lock` не создаём. Lockfile коммитится.
- Build-скрипты зависимостей по умолчанию выключены; разрешения — в `pnpm-workspace.yaml` (`allowBuilds`), с комментарием зачем.
- Обновление мажорных версий — отдельной задачей с прогоном `pnpm check`.
- Не добавляем: UI-киты, CSS-in-JS, lodash/moment и аналоги, state-менеджеры, вторую query-библиотеку — пока в реестре «Кандидаты» не выполнено условие.

## Реестр

### Runtime

| Пакет | Зачем | Альтернативы | Как заменить |
|---|---|---|---|
| `react`, `react-dom` | UI | — | — |
| `@tanstack/react-query` | кэш, отмена, дедупликация и повторы запросов (D-22) | свой `useRequest` (был до D-22), SWR | импортируется только в `src/api/queryClient.ts`, фабриках `*Queries.ts`, `QueryProvider` и фичевых хуках |
| `hono`, `@hono/node-server` | HTTP-сервер backend (D-58) | `node:http` (свой роутер, CORS, парсинг), Fastify (избыточен), Express (устарел) | только `server/main.ts`, `server/app.ts`, `server/routes/` (ESLint, блок 8) |
