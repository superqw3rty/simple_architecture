# Стиль кода

## Лимит 120 строк

Любой файл в `src/` — не больше 120 строк кода (пустые строки и комментарии не считаются). Для TS/TSX это проверяет ESLint (`max-lines`), для SCSS — `pnpm check:arch`. Ориентир для хорошего файла — около 70 строк.

Зачем: файл должен читаться как оглавление книги — набор понятных абстракций, детали которых спрятаны в соседних файлах.

Когда файл растёт, **не сжимай** код (однострочники, короткие имена, удаление пустых строк), а раздели по смыслу:

| Что разрослось | Как делить |
|---|---|
| View | выдели блок JSX в дочерний компонент `components/Child/` |
| Презентер | выдели связанную группу состояния и эффектов в хук `useSomething.ts` |
| Хук | выдели чистые вычисления в функцию `doSomething.ts` |
| Чистая функция / модуль | раздели по ответственности, общий тип — в `types.ts` |
| SCSS | это сигнал, что view пора делить на дочерние компоненты |
| Тест | раздели по тестируемым сценариям: `name.cache.test.ts` |

Делить нужно по смысловым границам, а не «первые 100 строк / остальное». У каждого нового файла должно быть имя, объясняющее его содержимое без открытия.

## Форматирование

- Форматирует Prettier (`.prettierrc.json`): одинарные кавычки, ширина 100, висячие запятые. Руками формат не правим: `pnpm format`. `pnpm check` падает на неотформатированном коде.
- **Тело `if` / `else` / `for` / `while` всегда в фигурных скобках и на отдельной строке**, даже если это одна инструкция (ESLint `curly: all`, чинится `eslint --fix`).

```ts
// ❌
if (value !== undefined) search.set(name, String(value));

// ✅
if (value !== undefined) {
  search.set(name, String(value));
}
```

Скобки не дают потерять вторую строку при правке, а лимит в 120 строк не повод их экономить — повод разделить файл.

## Именование

- Компоненты и их папки — `PascalCase`; хуки — `useCamelCase`; функции и переменные — `camelCase`; константы модуля — `UPPER_SNAKE_CASE`.
- Файл называется так же, как его главный экспорт: `paginate.ts` → `paginate`.
- Булевы — `is*`, `has*`, `can*`, `should*`. Обработчики в пропсах — `on*`, внутри презентера — `handle*`.
- Пропсы компонента — интерфейс `ComponentNameProps` в файле view (или в `types.ts`, если нужен презентеру).
- Без сокращений: `button`, `event`, `index`, а не `btn`, `e`, `i` (исключение — общепринятые `id`, `url`, `dto`).

## TypeScript

- `strict` + `noUncheckedIndexedAccess`. Без `any`; `unknown` + сужение типа. `as` — только на границе с внешним миром (ответ сервера, DOM).
- Импорт типов — `import type { ... }` / `import { type X }`.
- Состояния с вариантами — дискриминируемые объединения, а не набор независимых булевых флагов.
- Возвращаемый тип презентера выводится автоматически; явный тип нужен для публичных функций `api/`, `utils/`, `hooks/`.
- Только именованные экспорты.

## React

- Только функциональные компоненты, объявление через `export function Name()`.
- Производные данные вычисляются при рендере (в презентере), а не синхронизируются через `useEffect` + `setState`.
- `useEffect` — только для синхронизации с внешним миром (таймеры, подписки, сеть через `useRequest`).
- `key` в списках — стабильный идентификатор, не индекс.

## SCSS

- Стили компонента — `ComponentName.module.scss` рядом с view, классы в `camelCase`: `styles.cardTitle`.
- Цвета, отступы, радиусы, шрифты, тени, длительности — только через CSS-переменные из `src/styles/tokens.scss` (`var(--color-accent)`). «Магических» значений в модулях нет.
- Из SCSS используем вложенность (не глубже 3 уровней), `&`-модификаторы и миксины для медиа-запросов. Переменные темы — CSS-переменные, не `$scss`.
- Варианты и состояния — `data-`/`aria-`атрибуты (`data-variant="ghost"`, `aria-pressed`), стили цепляются за атрибут: `&[data-variant='ghost']`. `className` во view — всегда один готовый класс из модуля, без склейки строк и инлайн-стилей. `style={{}}` — только для значений, приходящих из данных.
- Компонент не задаёт себе внешние отступы (`margin`) — расположением управляет родитель.
- Mobile-first, базовая проверка на ширине 375px. Анимации уважают `prefers-reduced-motion`.

## Доступность

- Интерактив — на нативных элементах (`button`, `a`, `input`), а не на `div` с `onClick`.
- У каждого поля есть подпись, у иконочной кнопки — `aria-label`. Переключаемые чипы — `aria-pressed`.
- Видимый фокус (`:focus-visible`) не убирается. Смена статуса загрузки объявляется через `aria-live`.

## Комментарии и тесты

- Комментарий объясняет **почему**, а не что. Экспортируемым хукам и функциям — одна строка JSDoc о назначении.
- Тесты — Vitest, файл `name.test.ts` рядом с кодом. Тестируем чистые функции и хуки (`renderHook`). View не тестируем: в нём нет логики.
- В тесте проверяется поведение (вход → выход), а не детали реализации.
