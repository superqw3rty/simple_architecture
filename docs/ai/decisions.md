# Журнал решений

Сюда записывается каждое архитектурное решение и каждое отступление от лекций курса. Формат: дата, решение, причина, на что влияет. Новые записи — в конец. Отменённое решение не удаляется, а помечается «заменено D-N».

## Неделя 1 — View + Presenter, дерево компонентов

### D-1. Презентер называется `useComponentName`, а не `usePresenter` — 2026-11-11
**В лекции:** `usePresenter.js` в каждой папке.
**Решение:** `useShowList.ts` для `ShowList`.
**Почему:** уникальные имена в поиске, вкладках редактора и стектрейсах.

### D-2. `index.ts` + `ComponentName.tsx` — 2026-11-11
**В лекции:** на выбор — `index.jsx` либо файл с именем папки.
**Решение:** оба сразу: view в `ComponentName.tsx`, `index.ts` только реэкспортирует.
**Почему:** короткий импорт `./components/ShowList` и нормальные имена вкладок. Цена — лишний файл на компонент.

### D-3. Дочерние компоненты лежат в `Parent/components/Child/` — 2026-11-11
**В лекции:** одноразовый дочерний компонент лежит прямо в папке родителя, а папка `components` означает «переиспользуется ниже по дереву».
**Решение:** все дочерние компоненты — в `components/` внутри родителя, и одноразовые, и общие для ветки.
**Почему:** в папке компонента его собственные файлы (view, презентер, хуки, стили) визуально отделены от дочерних компонентов.
**Последствие:** папка `components` больше не маркер переиспользования. Смысл теперь такой: «используется на этом уровне и ниже». Признак переиспользования — расположение выше места использования.

### D-4. SCSS Modules вместо чистых CSS Modules — 2026-11-11
**В лекции:** обычные CSS Modules без препроцессоров.
**Решение:** `*.module.scss`.
**Почему:** вложенность и миксины для медиа-запросов. Тема при этом — на CSS-переменных, не на `$scss`.

### D-5. Презентер не обязателен для компонентов без логики — 2026-11-11
**Решение:** `components/ui/*` — без хуков вообще; компонент «пропсы → JSX» не получает пустой презентер. Самодостаточные компоненты и любые компоненты с логикой — всегда с презентером.
**Почему:** пустой хук — шум. Граница однозначна: первая строка логики → создаётся презентер.

### D-6. `memo` разрешён во view — 2026-11-11
**Решение:** `memo`, `forwardRef` допустимы в `.tsx`; все хуки React — запрещены.
**Почему:** `memo` — декларативная оптимизация рендера, не логика. Кастомный компаратор — логика, выносится в `.ts`.

### D-7. Лимит 120 строк распространяется на SCSS и тесты — 2026-11-11
**Почему:** длинный файл стилей — признак того, что view пора делить.

### D-8. Собственный `useRequest` вместо TanStack Query — 2026-11-11 (заменено D-22)
**Почему:** challenge домашнего задания. Контракт совместим с `useQuery`, фичи используют его только через свои хуки-обёртки → переезд описан в `data-fetching.md`.

### D-9. Кэш запросов — модульный синглтон — 2026-11-11 (заменено D-22)
**Решение:** `requestCache.ts` вне React, подписка через `useSyncExternalStore`.
**Почему:** кэш общий для всего приложения без провайдера; `useSyncExternalStore` избавляет от `setState` в эффектах и даёт дедупликацию между компонентами.
**Риск:** глобальное состояние в тестах — лечится `clearCache()` в `beforeEach`.

### D-10. Слои до появления Interactor/Entity — 2026-11-11
**Решение:** пока курс не ввёл остальные слои VIPER: сеть — `src/api`, доменные типы — `src/types` (уточнено в D-14), бизнес-вычисления — чистые функции рядом с презентером.
**Пересмотреть:** после лекции про Interactor/Entity.

### D-11. TypeScript 6.x — 2026-11-11
**Почему:** `typescript-eslint` 8 требует `typescript <6.1`. Обновить, когда выйдет поддержка TS 7.

### D-12. Фигурные скобки у любого блока + Prettier — 2026-11-11
**Решение:** ESLint `curly: all`; форматирование — Prettier, `format:check` входит в `pnpm check`.
**Почему:** единый вид кода без обсуждений; однострочный `if` без скобок легко сломать при правке.
**Связь с D-7:** скобки добавляют строки — лимит 120 от этого не ослабляется.

### D-13. Каждый общий хук — в своей папке — 2026-11-11
**Решение:** `src/hooks/useName/{index.ts, useName.ts, useName.test.ts}`; файлов прямо в `src/hooks/` нет. Сложный хук документируется в `README.md` рядом.
**Почему:** хук, тест и его внутренние части лежат вместе; структура одинаковая для простых и составных хуков. Проверяется `check:arch`.

### D-14. Общие типы — в `src/types` — 2026-11-11
**Решение:** `src/types/<entity>.ts` — доменные типы, `src/types/api/<service>.ts` — типы ответов серверов. Папка `src/models` и файлы `dto.ts` внутри сервисов не используются.
**Почему:** все общие типы в одном предсказуемом месте; ответ API типизирован полностью и виден без открытия кода запроса.
**Ограничение:** `@/types/api/*` импортируется только из `src/api` — UI по-прежнему зависит от доменных типов, а не от формы ответа сервера. Во view запрет проверяет ESLint.

### D-15. Варианты и состояния — через `data-` и `aria-`атрибуты — 2026-11-11 (запрет склейки `className` снят в D-29)
**Решение:** view не собирает `className` из строк. Вариант компонента — `data-variant`, `data-size`, `data-tone`; состояние — нативные `aria-pressed`, `aria-current`, `disabled`. Стили цепляются за атрибут.
**Почему:** склейка классов — это вычисление во view; атрибуты декларативны, а `aria-*` заодно дают доступность.

### D-16. Шрифты — Google Fonts через `<link>` — 2026-11-11 (заменено D-30)
**Решение:** Fraunces и Manrope подключены в `index.html`, в токенах есть системные фолбэки.
**Почему:** ноль зависимостей. Пересмотреть (self-host через пакет), если понадобится работа без внешних запросов.

### D-17. Брейкпоинты — SCSS-миксин `bp()` в модулях компонентов — 2026-11-13 (имена заменены D-19)
**Решение:** `src/styles/breakpoints.scss` с картой `$breakpoints` (пока `md: 768px`) и mobile-first миксином `bp()`, подключается автоматически через `additionalData`. Медиа-запросы по ширине пишутся в модуле компонента, значения берутся из шкалы токенов (добавлен `--text-lg-plus: 1.25rem`).
**Почему:** `var()` не работает в условии `@media`, так что брейкпоинты в любом случае живут в SCSS. Один механизм покрывает и типографику, и раскладку. Адаптивность компонента видна рядом с ним. Конкретизирует D-4.
**Рассмотрено и отклонено:** семантические токены с переопределением в `tokens.scss` (по токену на каждый элемент, раскладку не покрывают); `clamp()` (промежуточные размеры не сверить с макетом); роли шкалы (в Figma типографика задана числами, без ролей); container queries (избыточно для текущих экранов).
**Проверка:** `pnpm check:arch` запрещает `@media` по ширине в `*.module.scss`.

### D-18. Шкала отступов `--space-N` = N × 4px, общая с Figma — 2026-11-13
**Решение:** шкала 4 · 8 · 12 · 16 · 20 · 24 · 32 · 48 · 64 · 80 · 120, имя шага — значение / 4 (`--space-5` = 20px). В Figma созданы переменные `space/*` (scope Gap, code syntax `var(--space-N)`), все padding/gap макета к ним привязаны. Значения макета вне сетки приведены к ней: 6→4, 9→8, 10→8 (у Brand 10→12), 13→12, 14→12, 22→20, 28→32. Размеры элементов вынесены в отдельные токены (`--logo-dot-size`, `--spinner-size`, `--status-symbol-size`).
**Почему:** в шкале не было 20/80/120 из макета, а `--space-5` = 24 не совпадало по смыслу ни с чем в Figma; размеры брались из spacing/radius-токенов по совпадению чисел. Именование по значению позволяет добавить шаг без перенумерации.
**Рассмотрено и отклонено:** токен на каждое значение макета (шкала перестаёт быть шкалой); порядковые номера с перенумерацией (ломаются при каждой вставке шага).
**Проверка:** `pnpm check:arch` — каждая `var(--x)` в модуле объявлена в `tokens.scss`, сырые `px`/`rem` в `padding`/`margin`/`gap` запрещены.

### D-19. Миксины `screen-from()` / `screen-below()`, брейкпоинт `tablet` — 2026-11-13 (уточнено D-21)
**Решение:** `bp()` переименован в `screen-from()` (`width >=`), добавлен `screen-below()` (`width <`) для чисто мобильных стилей. Ключ `md` переименован в `tablet`. Условия в range-синтаксисе Media Queries 4.
**Почему:** `bp(md)` не читается без знания соглашения; `screen-from(tablet)` / `screen-below(tablet)` читаются как фраза. Без max-width мобильные стили приходилось задавать в базе и сбрасывать на планшете. Range-синтаксис даёт непересекающиеся диапазоны ровно на 768px без хаков вида `767.98px`.
**Рассмотрено и отклонено:** `up`/`down` в стиле Bootstrap (неочевидно, включается ли граница); `max-width: 767.98px` (магическое число).
**Проверка:** `pnpm check:arch`, как в D-17.

### D-20. Высота строки — шкала `--leading-*` — 2026-11-13
**Решение:** `line-height` задаётся только безразмерными токенами: `none` 1 · `tight` 1.1 · `snug` 1.2 · `normal` 1.4 · `relaxed` 1.5 · `loose` 1.6. Значения из Figma (px) переводятся делением на размер шрифта и округляются до ближайшего шага. Заголовок результатов приведён с 1.15 к `snug` (в макете 36 / 30 = 1.2).
**Почему:** безразмерный коэффициент наследуется корректно и не требует переопределения на брейкпоинтах; раньше в модулях были разрозненные числа (1.15, 1.2, 1.4, 1.6), и сверка с макетом шла на глаз.
**Рассмотрено и отклонено:** px-токены по макету (переопределение на каждом брейкпоинте, неверное наследование); переменные line-height в Figma (Figma привязывает высоту строки только в px, коэффициент не выразить).
**Проверка:** `pnpm check:arch` запрещает `line-height` без `var(--leading-*)` в `*.module.scss`.

### D-21. Разные на экранах значения — в обоих миксинах — 2026-11-13
**Решение:** в базе модуля — только общие для всех экранов стили. Значение, которое отличается, задаётся парой `screen-below(tablet)` + `screen-from(tablet)`, без мобильного значения в базе.
**Почему:** диапазоны не пересекаются, поэтому мобильный CSS не попадает в десктоп и не перебивается там; каждое объявление читается как «это для такого-то экрана». Уточняет D-19, где `screen-below` был только для чисто мобильных стилей.

## Неделя 2

### D-22. TanStack Query вместо собственного `useRequest` — 2026-11-15
**Решение:** запросы из React — `@tanstack/react-query` v5. `src/hooks/useRequest` и `useLatestRef` удалены. Ключи и функции запросов собираются только в фабриках `src/api/<service>/<entity>Queries.ts` через `queryOptions()`; фича вызывает `useQuery(showQueries.search(term))`. Клиент — `createQueryClient()` в `src/api/queryClient.ts` (4xx не повторяем, остальное — до 2 повторов; `refetchOnWindowFocus: false`), провайдер — `src/QueryProvider`, презентер создаёт клиент через `useState`.
**Почему:** решение пользователя — не поддерживать собственный кэш запросов; challenge «без `useQuery`» из hw1 снят. Фабрика держит ключ, `signal` и `staleTime` в одном месте — в фичах их легко рассинхронизировать.
**Отступление:** `src/api` импортирует `QueryClient` и `queryOptions` из `@tanstack/react-query` — это функции без React; `react`, хуки и компоненты в `src/api` по-прежнему запрещены.
**Рассмотрено и отклонено:** отдельный слой `src/queries` (ключ далеко от эндпоинта, ещё одна папка без выгоды); ключи в фичевых хуках (дублирование, риск потерять `signal`); `new QueryClient()` в `main.tsx` (view не импортирует `@/api`).
**Проверка:** ESLint — во view из TanStack можно только `QueryClientProvider`; в `src/api` — только `QueryClient` и `queryOptions`, без `react`, `@/hooks`, `@/components`. Ключи вне фабрик — пункт `arch-review`.

### D-23. Провайдеры приложения — в `src/<Name>/`, не в `src/components/` — 2026-11-18
**Решение:** `QueryProvider` перенесён из `src/components/` в `src/QueryProvider/`. Провайдеры и обёртки, которые использует только точка входа, лежат рядом с `main.tsx` (пункт 5 дерева решений в `structure.md`).
**Почему:** `src/components/` — для компонентов, используемых в разных ветках; у провайдера один потребитель — `main.tsx`.

### D-24. Карточка шоу в макете — горизонтальная, постер 168px с пропорцией 42∶59 — 2026-11-19 (сетка списка заменена D-25, затем D-27)
**Решение:** в Figma `ShowCard` и `ShowCardSkeleton` — наборы вариантов `Size=Default` (десктоп) и `Size=Compact` (мобильный). Default: отступы 24, постер 168×236, заголовок 26/31, описание 16/26 в 3 строки, карточка 384px в высоту. Название — максимум 3 строки с многоточием (Figma: Truncate text, Max lines 3; в коде `-webkit-line-clamp: 3` + `overflow-wrap: anywhere`, полное название в `title`), поэтому высота карточки не зависит от данных; на Results третья карточка — пример длинного названия. Compact: отступы 20, постер 126×177, заголовок 20/24, карточка 313px. Постер слева, справа мета, название, жанры; описание под ними на всю ширину. У постера Lock aspect ratio 42∶59 (TVMaze отдаёт постеры 210×295), картинка — `cover`, рейтинг лежит на фото. Список — сетка: 3 колонки от `tablet`, 1 на мобильном. В коде карточку по макету верстает автор (домашнее задание); сейчас в коде только постер с `aspect-ratio: 42 / 59` и мета-строка.
**Почему:** приложение про информацию о шоу: вертикальная карточка с постером на всю колонку (416×585 на 1440) занимала весь экран, а постер 120px выглядел слишком мелко. 168px — середина: ряд из 3 карточек помещается в экран 1440×900 вместе с описанием. На 375px постер 168 оставлял тексту ~120px, поэтому мобильному нужен свой вариант.
**Рассмотрено и отклонено:** постер-баннер фиксированной высоты с `cover` (срезает название на постере); постер 120px (слишком мелко); больше колонок с мелкими вертикальными карточками (описанию не хватает ширины); один размер постера для всех ширин (на мобильном текст в узкой колонке по 4 строки).

### D-25. Число колонок списка шоу — от минимальной ширины карточки, без брейкпоинтов — 2026-11-20 (заменено D-27)
**Было:** 3 колонки от `tablet` (768px), 1 на мобильном (D-24).
**Проблема:** горизонтальной карточке нужно 224px на постер и отступы (168 + 16 + 2 × 20). На 1024 при трёх колонках карточка ~277px, и тексту оставалось 56–94px: заголовок и жанры вылезали за карточку. При 1280 — 138px, впритык; нормально (~197px) только с 1440.
**Решение:** `ShowList` — `repeat(auto-fill, minmax(min(100%, var(--show-card-min-width)), 1fr))`, токен `--show-card-min-width: 400px`. У варианта `Default` в Figma на всё, кроме текста, уходит 236px (отступы 2 × 24, постер 168, зазор 20), значит тексту остаётся ≥ 164px; сам мастер-компонент шириной 384 оставляет 146, так что 400 укладывается в допуск макета. С текущими отступами страницы (D-26): 1 колонка до ~900px, 2 — до ~1390px, 3 — с 1440 (как в Figma). `auto-fill`, а не `auto-fit`: при одном-двух результатах карточки не растягиваются на всю ширину. `min(100%, …)` даёт единственной колонке сжаться на узком телефоне без переполнения.
**Почему:** пороги колонок выводятся из того, что реально нужно карточке, и сами сдвигаются при смене отступов страницы, размера постера или `max-width` у `#root`. С брейкпоинтами их пришлось бы пересчитывать вручную, и 1140 для трёх колонок, как предполагалось сначала, не работает: тексту ~92px.
**Рассмотрено и отклонено:** брейкпоинты `desktop: 1024` (2 колонки) и `wide: 1440` (3 колонки) — тот же результат, но пороги — магические числа, привязанные к текущим отступам; 2 колонки от `tablet` — на 768 тексту ~76px; container queries в карточке (постер наверх в узкой карточке) — отложено, при auto-fill карточка уже не бывает уже 400px, кроме мобильного, где есть свой вариант `Compact`.
**Ограничение:** точные пороги в коде не видны — они в комментарии к токену и здесь. Брейкпоинты по-прежнему нужны, когда меняется сама раскладка карточки, а не число колонок.
**Figma:** переменная `size/show-card-min-width` = 400 в коллекции `Tokens` (scope Width/Height, code syntax `var(--show-card-min-width)`). Добавлены кадры `Laptop / Results` (1024: две колонки по 436, третья карточка страницы — во втором ряду, половинной ширины) и `Tablet / Results` (768: одна колонка 704, поле поиска заполняет остаток TopBar). В новых кадрах `ShowList` — auto layout с переносом, у карточек привязан `minWidth`. Точного аналога `auto-fill` в Figma нет: при Fill одиночная карточка последнего ряда растягивается на весь ряд, поэтому на 1024 ширина колонок задана фиксированно. Кадры 1440 и 375 не менялись — код с ними совпадает.

### D-26. Брейкпоинт `desktop: 1024px`, миксин `screen-between()`, токен `--page-gutter` — 2026-11-20 (`desktop` перенесён на 1200 в D-27)
**Решение:** боковой отступ страницы — `--page-gutter` в `tokens.scss`: 16px на мобильном, 32px на планшете (768–1023), 64px с 1024. Его используют `Header` и `MainContent` через `padding-inline`, без своих медиа-запросов. Для трёх диапазонов добавлены брейкпоинт `desktop: 1024px` и миксин `screen-between($from, $to)` (`from <= width < to`). `tokens.scss` подключает `breakpoints.scss` явно: это partial, `additionalData` из `vite.config.ts` в него не попадает.
**Почему:** 64px с каждой стороны на 768 съедали шестую часть экрана. Отступ меняется в двух компонентах одновременно, иначе край шапки и списка расходятся, — по правилу из `code-style.md` это повод для семантического токена. `screen-between` сохраняет непересекающиеся диапазоны из D-19/D-21 вместо перебивания `screen-from(tablet)` через `screen-from(desktop)`.
**Рассмотрено и отклонено:** три миксина в каждом из двух модулей (дублирование, отступы легко разъедутся); `clamp()` для отступа (отклонён в D-17 — промежуточные значения не сверить с макетом); `screen-from(desktop)` поверх `screen-from(tablet)` (перебивание, против D-21).
**Проверка:** `pnpm check:arch` по-прежнему запрещает сырые `@media` по ширине в `*.module.scss`; сообщение об ошибке упоминает `screen-between`.
**Figma:** тариф файла позволяет один режим на коллекцию, поэтому одна переменная с режимами Mobile/Tablet/Desktop невозможна. Вместо неё в `Tokens` три переменные `layout/page-gutter/mobile|tablet|desktop` — ссылки на `space/4`, `space/8`, `space/16`, scope Gap, у всех code syntax `var(--page-gutter)`. Боковые отступы TopBar и Content на всех экранах привязаны к ним (десктоп 1440 и 1024 — `desktop`, 768 — `tablet`, 375 — `mobile`). Если тариф позволит режимы — заменить тройку одной переменной в коллекции `Layout` с режимами и назначать режим кадру.

### D-27. Список шоу — 1 или 3 колонки; карточка `Compact` на 1200–1439 — 2026-11-20
**Проблема:** по hw1 на странице 3 шоу. D-25 давал 2 колонки на ~900–1390px, и каждая полная страница заканчивалась одной карточкой во втором ряду.
**Решение:** число колонок — делитель размера страницы. Раскладка:

| Ширина | Колонки | Вариант `ShowCard` | `--page-gutter` |
|---|---|---|---|
| < 768 | 1 | `Compact` | 16 |
| 768–1199 | 1 | `Default` | 32 |
| 1200–1439 | 3 | `Compact` | 64 |
| ≥ 1440 | 3 | `Default` | 64 |

Брейкпоинты: `tablet: 768`, `desktop: 1200`, `wide: 1440`. `desktop` 1200 — ширина, с которой три карточки `Compact` (постер 126, отступы 2 × 20, зазор 16) оставляют тексту ≥ 150px (карточка 336–341px); `wide` 1440 — то же для `Default` и ширина десктопного кадра Figma. Сетка — `minmax(0, 1fr)` ниже `desktop`, `repeat(3, minmax(0, 1fr))` от `desktop`. Варианты карточки — миксины `card-compact` / `card-default` в `ShowCard/_variants.scss`: диапазоны несмежные (Compact — мобильный и 1200–1439), поэтому каждый миксин — пара непересекающихся медиа-запросов. Токен `--show-card-min-width` удалён — колонки больше не считаются от него.
**Почему:** при 3 шоу на странице 2 колонки всегда дают неполный ряд. Три колонки `Default` помещаются только с ~1390px, а `Compact` — с 1200, поэтому на распространённых ноутбуках 1280 тоже три карточки. Оба варианта уже есть в Figma, новый дизайн не нужен.
**Рассмотрено и отклонено:** `auto-fill` по минимальной ширине (D-25) — даёт 2 колонки; 2 колонки с растянутой на весь ряд последней карточкой (`grid-column: 1 / -1`) — карточки разного размера на одной странице без смысловой причины; одна колонка `Default` вплоть до 1440 — на 1280 строка описания ~130 символов; вертикальная карточка для 3 колонок с 1024 — постер ~390px в высоту, отклонено ещё в D-24; оставить «2 + 1».
**Компромисс:** на 1024–1199 одна карточка `Default` шириной до ~1120px, строка описания длинная (~130 символов), но описание обрезано до 3 строк.
**Figma:** кадр `Laptop / Results` теперь 1200 — три `ShowCard` `Size=Compact`, отступ `layout/page-gutter/desktop`. `Tablet / Results` (768, представляет 768–1199) — `ShowList` вертикальный, одна колонка `Default`. Переменная `size/show-card-min-width` удалена; описания `layout/page-gutter/tablet|desktop` обновлены под 768–1199 и 1200+. Добавлены `Tablet / Start`, `Tablet / Error`, `Tablet / Empty` (768 × 1024): отступ `layout/page-gutter/tablet`, поле поиска — Fill с прежней шириной как максимумом (480 в TopBar, 720 в Hero), заголовок Start — Fill с максимумом 900. Кадров 1200 для Start / Error / Empty нет — там нет сетки, и они совпадают с 1440. Правило вариантов записано в описание компонента `ShowCard`; аннотации в файле недоступны (нет прав на их редактирование).

## Неделя 3

### D-28. Компоненты объявляются через `export const Name: FC<NameProps>` — 2026-11-23
**Было:** `export function Name()` (`code-style.md`, раздел React).
**Решение:** каждый компонент — `export const Name: FC<NameProps> = (props) => …`; компонент без пропсов — `FC` без параметра. Хуки, презентеры и чистые функции — без ограничений.
**Почему:** решение автора проекта: единый вид объявления компонентов, тип пропсов виден в сигнатуре через `FC`.
**Проверка:** ESLint запрещает `export function` в `*.tsx`.

### D-29. Склейка `className` во view разрешена — 2026-11-23
**Было:** view не собирает `className` из строк (D-15).
**Решение:** `className` — на усмотрение автора: один класс модуля, шаблонная строка из нескольких классов (в том числе глобального `container`) или тернарник по готовому флагу. Варианты через `data-`/`aria-`атрибуты по-прежнему уместны для ui-компонентов, но не обязательны.
**Почему:** решение автора проекта: выбор класса по готовому флагу — рендер-синтаксис того же уровня, что `condition && <X />`, а не логика.

### D-30. Шрифты — self-hosted — 2026-11-23
**Было:** Google Fonts через `<link>` в `index.html` (D-16).
**Решение:** файлы `woff2` лежат в `src/assets/fonts/`, `@font-face` — в `src/styles/fonts.scss` с `font-display: swap`, подключён из `global.scss`. Внешних запросов за шрифтами нет.
**Почему:** решение автора проекта: без зависимости от внешнего CDN, шрифты приходят вместе с бандлом и кэшируются с ним.

### D-31. Скелетон — дочерний компонент, экспортируется рядом с компонентом — 2026-11-23
**Было:** три способа: `PaginationSkeleton` — отдельный компонент, `ShowList` и `GenreChips` — проп `isLoading` с веткой внутри.
**Решение:** у каждого блока со скелетоном — `Name/components/NameSkeleton/`, `Name/index.ts` реэкспортирует оба. Экран собирает скелетон из скелетонов блоков (`ResultsSkeleton`), сами блоки про загрузку не знают. Общая раскладка блока и скелетона — partial с миксинами (`_grid.scss`, `_chip-row.scss`, `ShowCard/_shell.scss`).
**Почему:** один способ вместо трёх; компонент данных не ветвится на `isLoading`; скелетон лежит рядом с тем, что изображает, и удаляется вместе с ним.
**Отступление:** `index.ts` отдаёт наружу два компонента — исключение из `structure.md` только для скелетонов.

### D-32. Автопроверки view и `index.ts` — 2026-11-23
**Решение:** ESLint в `*.tsx` запрещает функцию в `on*`-атрибуте (`onClick={() => …}`) и `export function` (D-28); во всём `src` — `no-console`. `check:arch` проверяет, что в `index.ts` только реэкспорты.
**Почему:** на ревью эти нарушения нашлись руками, хотя проверяются автоматически.
**`key` в списках:** `eslint-plugin-react`, правило `react/jsx-key` (с `checkFragmentShorthand` и `warnOnDuplicates`) — добавлено по решению пользователя 2026-11-23, запись в `dependencies.md`.

### D-33. Центрирование — забота родителя — 2026-11-23
**Решение:** `margin: 0 auto` и `margin-inline: auto` в модуле компонента не используются. Компонент задаёт только свой размер (`max-width`), а в середину его ставит родитель: `align-items: center` у своего flex-контейнера или обёртка `.status { display: flex; justify-content: center }`, если остальным детям нужно растягиваться (`MainContent`).
**Почему:** правило «компонент не задаёт себе внешние отступы» распространяется и на авто-отступы: тот же `StatusMessage` в другом месте может понадобиться выровненным влево, и тогда его стиль пришлось бы перебивать.
**Рассмотрено и отклонено:** разрешить `margin-inline: auto` как исключение для блока с `max-width` — короче, но компонент снова решает, где стоять.

### D-35. Все размеры кратны 4 — 2026-11-23
**Решение:** сетка 4px распространяется на всё, кроме толщины обводки и `--radius-pill`. Вне сетки — округление до ближайшего кратного 4, при равенстве вверх.
- **Шрифты:** шкала `--text-N` с номером шага = px / 4, как `--space-N`: 14 → 16 (кнопки, чипы, страницы, рейтинг, «Try»), 18 → 20 (описание hero, поиск от `tablet`, логотип на мобильном — теперь 20 везде), 30 → 32 (заголовок результатов и статуса на мобильном), 26 удалён (не использовался). Старые имена `--text-xs…3xl`, `-plus`, `--text-symbol` удалены.
- **Высота строки:** вместо коэффициентов `--leading-none…loose` — длины `--leading-N` (px / 4); пары 12/16, 16/24, 20/28, 20/24 (логотип), 20/32 (hero), 32/40, 40/48, 44/52, 72/72, 76/84. Описание статуса 16/26 → 16/24, подсказка 16/22 → 16/24. `font-size` без `line-height` в том же блоке запрещён.
- **Формы и элементы:** `--radius-sm` 10 → 8, `--radius-md` 14 → 12 (поглотил `--page-button-radius`); высоты контролов `--control-height-xs` 36 (чип, был 37), `-sm` 44 (кнопка, кнопка страницы; заменил `--page-button-size`), `-md` 52 (поиск); постер Compact 126×177 → 128×180; точка логотипа 10 → 12; фокус-кольцо 3 → 4; иконка поиска 22 → 24, звезда 12×11 → 12×12; скелетон: чипы 72/100/96/112 × 36, строки карточки 16/28/24/16.
- **Автоматизация:** `pnpm check:arch` проверяет, что длины в `tokens.scss` кратны 4 и шаг N = N × 4px, и что каждый блок с `font-size` содержит `line-height`.
**Почему:** пользователь закрыл открытый вопрос D-34: одна сетка для всех размеров, без исключений для типографики. Коэффициенты высоты строки не дают кратных 4 значений (28 × 1.2 = 33.6), поэтому высота строки задаётся длиной. Нумерация по px / 4 делает правило видимым в имени токена и проверяемым автоматически.
**Отличие от прежнего:** заменяет правило «`line-height` — безразмерный коэффициент» из `code-style.md`.
**Figma:** ещё не обновлена — упёрлись в лимит вызовов Figma MCP на тарифе Starter. Нужно привести тексты, `radius/sm`/`radius/md`, высоты чипов и кнопок, постер Compact, точку логотипа и иконки к значениям выше.

### D-36. Переход Start → Results без анимации, раскладка — по значению после debounce — 2026-11-24
**Решение:** debounce живёт в `useShowsExplorer`: `term` = `query.trim()` после паузы 400 мс, `isCompact = term.length > 0`. `term` уходит в `MainContent`, `useShowsSearch(term)` получает готовое значение и сам не дебаунсит. Пустое поле сбрасывает `term` сразу, без ожидания. `Hero` и `ExampleChips` снимаются условным рендером, анимации нет, `--duration-base` не нужен. Поле поиска остаётся одним DOM-узлом, поэтому фокус и каретка не теряются.
**Почему:** раньше `isCompact` считался по `query` до debounce: на первой букве hero пропадал, а результатов ещё не было, и 400 мс под шапкой было пусто. Теперь раскладка меняется один раз — вместе с отправкой запроса. Анимацию пользователь счёл ненужной.
**Отличие от прежнего:** в продуктовом решении `hw1.md` было «hero плавно сворачивается (~300 мс)». Гайд `hw1-stage2.md` (раздел 4) обновлён.

### D-37. Смена результатов объявляется постоянным live-регионом — 2026-11-24
**Решение:** `MainContent` всегда рендерит визуально скрытый `<p aria-live="polite">`, даже на старте. Текст — одна короткая фраза из `getAnnouncement`: «Searching for “term”…», «10 shows for “term”», «No shows for “term”» или текст ошибки. Заголовок `Results` тоже live: выбор жанра меняет число в нём. У `StatusMessage` больше нет `role="status"` — объявляет родитель. Тексты ошибки лежат в `ErrorComponent/constants.ts` и общие для экрана и объявления.
**Почему:** live-регион, который появляется в DOM вместе с текстом, скринридеры читают ненадёжно. Регион, который есть всегда, объявляет каждое изменение. `aria-live` на всём `<main>` прочитал бы весь список карточек. Второй источник объявлений (`role="status"` у сообщения) давал бы дубли.
**Отличие от гайда:** гайд предлагал обернуть в `aria-live` всю область результатов.
