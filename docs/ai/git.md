# Коммиты

Коммит — единица ревью и отката. Коммит на 100+ файлов нельзя ни прочитать, ни откатить по частям: в нём смешаны фича, рефакторинг и форматирование.

## Правила

- **Один коммит = один логический шаг**: компонент с презентером, стилями и тестами; одно правило с записью в `decisions.md`; один рефакторинг.
- **Ориентир — не больше 25 файлов** (изменённые + новые). Больше — почти всегда два шага в одном коммите.
- **Механические массовые правки — отдельным коммитом без логики**: переименование, переезд папок, `pnpm format`, обновление lockfile. Так ревьюер пролистывает их, а не ищет в них изменения поведения.
- Перед коммитом `pnpm check` зелёный: каждый коммит — рабочее состояние, на которое можно откатиться.
- Сообщение — на английском, в повелительном наклонении, о том, *что* сделано: `Add ShowCard presenter`, а не `fixes`.

## Что делает агент

- Коммитит и пушит **только по явной просьбе** пользователя (см. `AGENTS.md`).
- Сам **предлагает** коммит, когда закончен логический шаг или сработал хук размера изменений. В предложении — группы файлов и сообщение для каждого коммита.
- Не начинает новый логический шаг поверх незакоммиченного большого изменения, не предложив сначала коммит.

## Автоматическая проверка

Хук Claude Code `.claude/hooks/diff-size.mjs` (`PostToolUse` в `.claude/settings.json`) после каждой правки и команды считает файлы в `git status`. Когда их становится 25, 50, 75…, он один раз добавляет агенту напоминание со списком папок. Пока изменений меньше порога — молчит; после коммита счёт начинается заново. Порог для проверки можно переопределить переменной `DIFF_WATCH_THRESHOLD`.

## Пример

✅ Три коммита: `Move shared helpers to MainContent/utils` (12 файлов), `Add focus handling to Pagination` (6 файлов), `Format with prettier` (30 файлов, без логики).

❌ Один коммит `1st week view and presenter` на 169 файлов: новые компоненты, переезд папок и правки стилей вперемешку.
