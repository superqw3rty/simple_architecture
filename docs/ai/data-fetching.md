# Загрузка данных

Запросы из React идут через собственный хук `useRequest` (`src/hooks/useRequest`). Готовую библиотеку (TanStack Query) не используем намеренно — это challenge домашнего задания. Контракт хука повторяет `useQuery`, чтобы переезд был дешёвым.

## Как писать запрос

1. API-функция в `src/api/<service>/` принимает `signal` и возвращает доменную модель (см. `api-layer.md`).
2. Фича оборачивает `useRequest` в **свой** хук рядом с презентером. Презентер и view про `useRequest` не знают.

```ts
// src/ShowsExplorer/useShowsSearch.ts
export function useShowsSearch(query: string) {
  const term = useDebouncedValue(query.trim(), SEARCH_DEBOUNCE_MS);

  return useRequest({
    key: ['shows', 'search', term],
    fn: ({ signal }) => searchShows(term, signal),
    enabled: term.length > 0,
    staleTime: 5 * 60_000,
  });
}
```

## Контракт `useRequest`

| Поле | Смысл |
|---|---|
| `key` | массив, однозначно описывающий запрос. Всё, от чего зависит ответ, обязано быть в ключе |
| `fn({ signal })` | функция запроса; `signal` обязательно пробрасывается в API-функцию |
| `enabled` | `false` — запрос не уходит, статус `idle` |
| `staleTime` | сколько мс данные из кэша считаются свежими (по умолчанию 0) |

Возвращает `{ data, error, status, isFetching, refetch }`, где `status`: `idle | pending | success | error`.

- `pending` — данных ещё нет, идёт первая загрузка → скелетоны.
- `isFetching` при `status: 'success'` — фоновое обновление устаревших данных → старые данные остаются на экране.
- `error` — всегда `Error` (обычно `ApiError`); показываем `error.message` и кнопку, вызывающую `refetch`.

## Обязательный UX запросов

- **Debounce** пользовательского ввода (`useDebouncedValue`, 300–500 мс). Запрос на каждую букву не отправляем.
- **Отмена**: смена `key` отменяет предыдущий запрос через `AbortController`. Вручную контроллеры в фичах не создаём.
- **Гонки**: ответ записывается, только если его запрос всё ещё актуален для ключа — поздний ответ старого запроса игнорируется.
- **Пустой ввод** → `enabled: false`, в сеть не идём, показываем начальное состояние.
- **Все четыре состояния** обязаны иметь UI: начальное, загрузка, ошибка с повтором, «ничего не найдено».
- Презентер переводит `status` в флаги для view (`isLoading`, `isEmpty`, `errorMessage`) — view не сравнивает строки статусов.

## Кэш приложения

`requestCache.ts` — модульный синглтон вне React, общий для всех вызовов `useRequest`.

- Запись хранится по `JSON.stringify(key)`; лимит 50 записей, вытесняются самые старые без подписчиков.
- **Дедупликация**: одновременные запросы с одним ключом делят один сетевой вызов.
- Запрос отменяется, когда отписался последний компонент, которому он был нужен.
- `invalidate(['shows'])` помечает устаревшими все ключи с этим префиксом; `clearCache()` — для тестов (`beforeEach`).
- Кэш живёт до перезагрузки страницы. В `localStorage` не пишем, пока нет требования.

Соглашение о ключах: `[сущность, действие, ...параметры]` — `['shows', 'search', 'batman']`. Параметры — примитивы или простые объекты с фиксированным порядком полей.

## Чего не делать

- Не вызывать `fetch` и API-функции из `useEffect` напрямую — только через `useRequest`.
- Не копировать `data` в `useState` — производные данные вычисляются при рендере.
- Не хранить в ключе то, что не влияет на ответ, и не забывать то, что влияет.
- Не глотать ошибки: `catch` без показа пользователю запрещён.

## Переезд на TanStack Query

Соответствие: `key` → `queryKey`, `fn` → `queryFn`, `enabled` → `enabled`, `staleTime` → `staleTime`, `refetch` → `refetch`, `invalidate(prefix)` → `queryClient.invalidateQueries({ queryKey: prefix })`, статус `idle` → `status === 'pending' && fetchStatus === 'idle'`.

Шаги:
1. Добавить пакет по `dependencies.md`, обернуть приложение в `QueryClientProvider` в `main.tsx`.
2. В фичевых хуках (`useShowsSearch` и т.п.) заменить `useRequest` на `useQuery`, адаптировать `idle`.
3. Удалить `src/hooks/useRequest`. API-функции, презентеры и view не меняются.

Чтобы это оставалось правдой: фичи не импортируют `requestCache` напрямую и не полагаются на поведение, которого нет в `useQuery`.

Когда пора переезжать: понадобились мутации с инвалидацией и оптимистичными обновлениями, бесконечная/серверная пагинация, фоновый refetch по фокусу или интервалу, повторы с backoff, devtools.
