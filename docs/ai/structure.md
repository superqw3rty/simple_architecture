# Структура файлов

Главная идея: **файловая структура отражает то, что видно на экране**. Чтобы найти код, достаточно пройти глазами по экрану сверху вниз: экран → блок → элемент.

## Карта репозитория

```
server/                    # backend (Hono), свои слои              → backend.md
shared/                    # контракт API фронт ↔ сервер: только типы
src/
  main.tsx                 # точка входа, только монтирование
  router/                  # маршруты TanStack Router               → routing.md
  styles/                  # tokens, breakpoints, mixins, fonts, global (→ styles.md)
  api/                     # сеть: http-клиент, сервисы, фабрики запросов, queryClient → api-layer.md
  tasks/                   # общие таски (нужны в нескольких ветках) → tasks.md
  stores/                  # клиентские сторы (Entity): toast-уведомления
  types/                   # общие типы: доменные (show.ts)
  hooks/                   # общие хуки без привязки к фиче
  utils/                   # общие чистые функции
  components/              # переиспользуемые компоненты всего приложения
    ui/                    # «глупые» кирпичики: Button, Chip, TextInput…
  <ComponentName>/         # самодостаточные компоненты: страницы, AppLayout, провайдеры
```

## Шаблон папки компонента

```
ShowList/
  index.ts                 # export { ShowList } from './ShowList';
  ShowList.tsx             # view
  ShowList.module.scss     # стили (если нужны)
  constants.ts  types.ts   # по необходимости
  logic/                   # вся логика компонента (D-55), есть только если есть логика
    useShowList.ts         # presenter
    useShowList.test.ts
    hooks/                 # доп. хуки презентера + тесты
      useSomethingElse.ts
      useSomethingElse.test.ts
    utils/                 # чистые функции для view + тесты
      someHelper.ts
      someHelper.test.ts
    tasks/                 # таски компонента (tasks.md): файл или папка + тесты
      doSomething.ts
      doSomething.test.ts
  ShowCard/                # дочерний компонент, нужен только ShowList
  ShowListSkeleton/        # скелетон ShowList (D-31)
  components/              # только общие для поддерева компоненты (D-42)
    Shared/
```

Правила:
- Одна папка = один компонент = один `.tsx`. Имя папки = имя компонента = имя `.tsx` (PascalCase).
- Презентер называется `use` + имя компонента и лежит в `logic/`: `logic/useShowList.ts`.
- Импорт компонента — всегда через папку: `import { ShowList } from './ShowList'`. В `index.ts` только реэкспорт, логики там нет.
- Наружу папка отдаёт только компонент (и, при необходимости, тип его пропсов). Всё из `logic/` — приватное, соседи это не импортируют.
- Скелетон загрузки — дочерний компонент того, что он изображает: `ShowList/ShowListSkeleton/`. Это единственное, что `index.ts` отдаёт наружу помимо самого компонента: `export { ShowListSkeleton } from './ShowListSkeleton'` (D-31).
- Папка компонента (PascalCase) отличается от служебной (`utils/`, `components/`) регистром имени. Общая раскладка компонента и его скелетона — SCSS-partial с миксинами в папке компонента (`ShowList/_grid.scss`), а не импорт чужого `.module.scss`.
- Только именованные экспорты, `export default` не используем.
- **Вся логика компонента — в `logic/`** (D-55, заменяет D-38). В корне папки компонента из `.ts` лежат только `index.ts`, `constants.ts`, `types.ts`. Внутри `logic/`: презентер в корне, остальные хуки — в `hooks/`, чистые функции — в `utils/`, таски — в `tasks/`; тест рядом с каждым файлом. В `logic/` и её подпапках нет `index.ts`: импорт напрямую `./logic/useResults`, `./utils/formatPageRange`. Почему: открыв любой компонент, видишь две части — JSX и стили сверху, всю логику в одной папке, разложенной по видам.
  - ✅ `Results/logic/utils/formatPageRange.ts` рядом с `Results/logic/useResults.ts`
  - ❌ `Results/formatPageRange.ts`, `Results/useResults.ts`, `Results/utils/formatPageRange.ts`

## Куда положить компонент — дерево решений

1. **Используется одним родителем** → папкой прямо в родителе: `Parent/Child/` (D-42).
2. **Используется несколькими компонентами одной ветки** → `components/` их ближайшего общего предка: `Ancestor/components/Shared/`.
3. **Используется в разных ветках приложения** → `src/components/`.
4. **«Глупый» кирпичик без логики и без знаний о домене** (кнопка, инпут, чип, спиннер) → `src/components/ui/`.
5. **Самодостаточный** — сам добывает данные, не зависит от пропсов родителя (экран, виджет) → `src/ComponentName/`.

Следствие: папка `components` внутри компонента — маркер переиспользования. В ней лежат только компоненты, которые импортируются **из двух и более папок** этого поддерева, и никогда — выше или в соседней ветке. Одноразовому компоненту там не место.

- ✅ `ShowsExplorer/Header/SearchInput/` — нужен только `Header`
- ❌ `ShowsExplorer/Header/components/SearchInput/`
- ❌ `ShowsExplorer/components/Header/` — `Header` нужен только `ShowsExplorer`

Почему: дерево папок повторяет экран без лишнего уровня на каждом шаге, а `components/` сразу говорит «это общее, правка заденет несколько мест». Удаляешь ветку — вместе с ней уходит всё, что нужно было только ей.

Вложенность не ограничена: 5–10 уровней — нормально, если это соответствует экрану.

### Перемещение

- Компонент понадобился второму потребителю → **перенеси** его на уровень общего предка (или в `src/components/`), не импортируй из чужой ветки через `../../`.
- Импорт вверх по дереву допустим только в папки `components`, `logic/utils/`, `logic/tasks/` и `constants.ts` предков и в общие `@/components`, `@/hooks`, `@/utils`, `@/tasks`, `@/stores`, `@/api`, `@/types` (D-45, D-55).
- Чистая функция, таска или константа нужна компоненту и его потомку (или нескольким потомкам) — она лежит в `logic/utils/`, `logic/tasks/` / `constants.ts` их ближайшего общего предка, а не реэкспортируется через `index.ts` одного из них (D-45).
  - ✅ `MainContent/logic/utils/formatResultsTitle.ts` — нужна `MainContent/logic/utils/getAnnouncement` и `Results/logic/useResults`
  - ❌ `Results/index.ts`: `export { formatResultsTitle } from './utils/formatResultsTitle'`
  - Почему: `index.ts` — витрина компонента; хелпер в ней привязывает соседей к внутренностям чужой ветки. У общего предка сразу видно, что значение общее и правка заденет несколько мест.
- Для всего, что дальше одного уровня вверх, используй алиас `@/`, а не цепочки `../../..`.

## Куда положить не-компонент

| Что | Куда |
|---|---|
| Хук нужен одному компоненту | `logic/hooks/` этого компонента |
| Чистая функция нужна одному компоненту | `logic/utils/` этого компонента |
| Таска нужна одному компоненту | `logic/tasks/` этого компонента |
| Чистая функция, таска или константа нужна нескольким компонентам одной ветки | `logic/utils/`, `logic/tasks/` / `constants.ts` их ближайшего общего предка (D-45) |
| Таска нужна в разных ветках приложения | `src/tasks/<taskName>/` (D-55) |
| Глобальное клиентское состояние (toast-уведомления) | `src/stores/<name>/` + хук подписки в `src/hooks/` (D-61) |
| Тип ответа нашего API, общий с сервером | `shared/` (D-58) |
| Хук нужен нескольким фичам, не знает о домене | `src/hooks/` |
| Чистая функция общего назначения | `src/utils/` |
| Доменный тип (`Show`) | `src/types/` |
| Тип ответа внешнего сервиса (TVmaze) | `server/tvmaze/types.ts` — на фронт не попадает (D-58) |
| Запрос к серверу, маппер, фабрика запросов (`queryKey`/`queryFn`) | `src/api/<resource>/<name>/`, инфраструктура — `src/api/core/` (`api-layer.md`, D-68) |
| Тип, нужный одному компоненту или хуку | `types.ts` в его папке, не в `src/types` |
| Константа одного компонента | в файле, где используется, или `constants.ts` в его папке |

### Общие хуки — `src/hooks/`

**Каждый хук — в своей папке**, даже если это один файл. Файлов прямо в `src/hooks/` не бывает.

```
src/hooks/
  useDebouncedValue/
    index.ts                    # export { useDebouncedValue } from './useDebouncedValue';
    useDebouncedValue.ts
    useDebouncedValue.test.ts
  useSomething/                 # хук из нескольких файлов
    index.ts                    # публичный API хука
    useSomething.ts
    parts.ts                    # внутренние части — снаружи не импортируются
    README.md                   # обязателен для хука из нескольких файлов
```

- Импорт — через папку: `import { useDebouncedValue } from '@/hooks/useDebouncedValue'`.
- Хук из нескольких файлов или с нетривиальным поведением получает `README.md`: параметры, результат, сценарии, ограничения.

### Общие типы — `src/types/`

```
shared/
  show.ts              # контракт API: Show, ShowsPage, FavoritesList — общие для фронта и сервера (D-58)
src/types/
  show.ts              # реэкспорт из shared + типы, нужные только фронту
```

Сырые ответы TVmaze (`TvMaze*`) живут только на сервере (`server/tvmaze/types.ts`), фронт с TVmaze не говорит.

- В `src/types` попадает только тип, который нужен **в нескольких местах** приложения. Пропсы компонента, результат хука, локальные типы остаются рядом со своим кодом.
- Один файл — одна сущность или один сервис. Файл назван по сущности: `show.ts` → `Show`.
- В файлах типов нет исполняемого кода: только `type`, `interface` и комментарии. Импорт — всегда `import type`.
- Каждое неочевидное поле подписано: единицы измерения, формат, когда бывает `null`.
- Сырых DTO на фронте нет (D-58). Если `src/types/api/` понадобится снова, его импортирует **только `src/api`** — ESLint (D-52).
- `shared/` содержит только типы: ни строчки исполняемого кода, ни импортов из `src/` или `server/`.

## Автопроверка

`pnpm check:arch` (`scripts/check-architecture.mjs`) проверяет структуру из этого файла; каждое сообщение об ошибке ссылается на правило. Полный список проверок — в самом скрипте. Добавляешь структурное правило — добавь проверку туда.

Раскладку `logic/` (D-55) проверяет `check:arch`, запрет React в `**/tasks/**` (D-54) — ESLint.
