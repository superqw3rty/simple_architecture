# TV Shows Explorer — правила для ИИ-агентов

Учебный проект курса **Simple Architecture** (Clean Architecture + VIPER для React).
Этот файл — точка входа. Он короткий намеренно: детали лежат в `docs/ai/`, читай нужный файл **до** того, как писать код.

## Пять правил, которые нельзя нарушать

1. **Компонент = view.** В `*.tsx` только JSX и один вызов своего презентера `useComponentName()`. Никаких `useState`/`useEffect`/вычислений/обработчиков с логикой.
2. **Логика — в `logic/` компонента:** презентер `logic/useComponentName.ts`, хуки, утилиты. **Бизнес-логика — в тасках:** обычная функция-глагол без React (`toggleFavorite`), см. `docs/ai/tasks.md`.
3. **Файл ≤ 120 строк** кода (TS, TSX, SCSS). Упёрся в лимит — дроби на хуки, функции, дочерние компоненты, а не сжимай код.
4. **Дерево папок повторяет экран.** Каждый компонент живёт в своей папке с `index.ts`; одноразовый — прямо в папке родителя, `components/` — только для общих. Подробно — см. `docs/ai/structure.md`.
5. **Сеть — только через `@/api`:** чтение из React — только `useQuery` с фабрикой из `@/api` (`showQueries.page({ term, genre, page })`), запись — только из таски, без `useMutation`.

ESLint ловит хуки, импорты `@/api`/`@/hooks` и обработчики с телом во view, лимит строк и `fetch` вне `@/api`; `pnpm check:arch` — структуру папок. Вычисления во view, полноту презентера и запросы только через фабрику не проверяет никто, кроме skill `arch-review`: зелёный `pnpm check` не значит, что правила соблюдены. Не отключай правила (`eslint-disable`) — меняй код.

## Рабочий процесс

1. Прочитай задачу и релевантные файлы из индекса.
2. Сначала спроектируй дерево компонентов (какие папки появятся), затем презентеры, затем view.
3. Новый компонент создавай по шаблону — skill `new-component`.
4. Логику (чистые функции, хуки, таски) покрывай тестами Vitest рядом с файлом: `name.test.ts`.
5. Запусти `pnpm check`. Красный результат = задача не готова.
6. Для UI-изменений проверь результат в браузере (`pnpm dev`).
7. Перед сдачей прогони skill `arch-review`.

## Как дополнять правила

Курс идёт по неделям, правила будут расширяться (interactor, entity, router…). Новое правило вносится через skill `add-rule`: файл в `docs/ai/` → строка в индексе выше → запись в `decisions.md` → по возможности автоматическая проверка в ESLint или `check-architecture.mjs`. Не раздувай этот файл.

## Прочее

- Доки и правила — на русском; код, имена, комментарии, тексты UI — на английском.
- Коммиты и пуши — только по явной просьбе пользователя.
- Если правило мешает сделать задачу хорошо — не обходи молча: предложи изменение правила и зафиксируй в `decisions.md`.
